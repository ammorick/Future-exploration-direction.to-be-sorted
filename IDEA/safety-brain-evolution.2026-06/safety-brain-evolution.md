## 🎯 演化路径（从当前到未来）

### 阶段1：静态过滤（已完成）
- 基于关键词的黑/白名单。  
- 优点：简单、快速、可解释。  
- 缺点：无法应对变体、新词、语义攻击。

### 阶段2：动态敏感词更新（近期目标）
- **方案A（自学习）**：通过用户反馈或语义模型自动识别新敏感词，但如何定义“敏感”？  
- **方案B（专用词库）**：定期从公开数据源（如GitHub敏感词库、政府封禁列表）拉取更新。  
- **方案C（调用外部API）**：使用第三方内容安全服务（如阿里云绿网、腾讯天御）。  
- **方案D（爬虫模块）**：定时爬取相关网站（如新闻、论坛）提取热门敏感词。  
**MVP 建议**：先实现方案B（定时拉取）或方案C（API调用），成本可控。

### 阶段3：底层不可绕过嵌入（中期目标）
- **目标**：让安全检测成为系统运行的**强制前提**，无法被上层代码跳过。  
- **技术选项**：  
  - 技术功底较弱，暂不列举
- **效果**：攻击者即使修改业务代码，也无法绕过安全检测。

### 阶段4：自我检测 + 简单修复（长期目标）
- **抛弃“敏感词”的概念**：安全不仅是内容过滤，还包括系统本身的异常检测。  
- **检测目标**：  
  - 线程池爆炸（并发资源耗尽）。  
  - 内存泄漏、磁盘满。  
  - 产生异常行为
  - 功能失效
  - API 调用持续失败。
  - 。。。。。。。。。  
- **修复动作**：  
  - 记录日志、重启异常组件。  
  - 降级返回默认回答。  
  - 通知管理员。

### 阶段5：可拔插微服务化（远期目标）
- 将安全大脑独立为一个微服务，主系统通过 API 调用。  
- 优点：便于升级、替换、扩展。  
- 缺点：网络延迟、额外运维成本。

## 🔭 与“地皮级安全”的关系

- **地皮级安全**（`ground-safety.md`）是从输入空间根本上约束不安全内容，属于**想法理念**。  
- **安全大脑演化**是在当前工程下（大模型 + 自然语言输入）不断加固防御，属于**工程演进**。  
- 两者不冲突：地皮级安全是遥远的理想，安全大脑演化是当下可落地的路径。
